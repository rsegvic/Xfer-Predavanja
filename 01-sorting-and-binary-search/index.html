Poglavlje 1

Sortiranje

Složiti podatke u smisleni poredak prema nekom kriteriju — i to brzo.

Zašto sortirati?

Algoritme za sortiranje koristimo kako bismo složili podatke u smisleni poredak prema nekom kriteriju. Primjena je puno šira od natjecateljskog programiranja: sortiranje je ključan preduvjet za mnoge druge algoritme — binarno pretraživanje je prvi primjer koji ćemo vidjeti.

  • Koliko brzo možemo sortirati? Koliko usporedbi je nužno?
  • Trebamo li uopće uspoređivati elemente?
  • Kada se isplati pisati vlastiti sort, a kada koristiti ugrađeni?
Dogovor Kroz cijelo predavanje brojit ćemo usporedbe dvaju elemenata. Usporedba je jedino što algoritam „vidi” o podacima.

O(n²) algoritmi: bubble sort

Algoritam se sastoji od n prolaza. U svakom prolazu uspoređujemo susjedne članove i zamijenimo ih ako nisu u poretku. Nakon prvog prolaza najveći je član na svom mjestu, nakon drugog i drugi najveći, …


for (int i = 0; i < n; i++) {
    for (int j = 0; j < n - 1; j++) {
        if (array[j] > array[j+1]) {
            swap(array[j], array[j+1]);
        }
    }
}

Kratak i razumljiv, ali za n = 10⁵ kvadratna složenost znači oko 100 sekundi — predaleko od vremenskog ograničenja.

Pustiti vizualizaciju do kraja: 45 usporedbi za n = 10. Najaviti: kasnije ćemo pokazati da je nužno samo 22. Vizualizacija preskače već složeni kraj niza (optimizirana varijanta); kod na slajdu je najjednostavniji oblik.

Može li brže? O(n log n) algoritmi

  • Merge sort — rekurzivno podijeli niz na dvije polovice, sortira svaku zasebno, a potom ih spoji (merge) u jedan sortirani niz.
  • Heap sort — radi nad strukturom binary heap; sličan selection sortu, ali najveći element pronalazi u O(log n).
  • Quick sort — odabere referentni element (pivot), ostale rasporedi lijevo/desno od njega i rekurzivno sortira obje strane. Varijante se razlikuju po izboru pivota.

Prekid unutarnje petlje bubble sorta kad nema zamjena pomaže u praksi, ali najgori slučaj ostaje O(n²). Ovi algoritmi su u najgorem (ili očekivanom) slučaju O(n log n).

Savjet Prije nego počnete pisati kod, dobro razmislite o složenosti. Tražite rješenje koje prolazi ograničenja, a zahtijeva najmanje vremena pisanja.

Može li još brže? Counting sort

Za algoritme koji uspoređuju elemente nije moguće bolje od O(n log n) — to ćemo dokazati na kraju predavanja. Brže je moguće samo ako ne uspoređujemo, nego iskoristimo dodatno znanje o podacima.

Counting sort: ako su svi brojevi iz malog intervala, npr. [0, 100], brojimo koliko se puta svaki pojavio, a zatim ih ispišemo redom.

Primjer: za niz [2, 44, 23, 25, 88, 44, 23] na poziciji 44 pomoćne liste piše 2, jer se broj 44 pojavljuje dva puta.

Složenost O(n + K), gdje je K raspon vrijednosti. Mana: memorija — izvedivo za brojeve do otprilike 10⁷, a zadaci često imaju puno veće.


int lista[101]; // na početku nule
for (int i = 0; i < n; i++) {
    cin >> x;   // brojevi koje unosimo
    lista[x]++;
}

// ispis sortiranog niza
for (int i = 0; i <= 100; i++) {
    for (int j = 0; j < lista[i]; j++)
        cout << i << ", ";
}

Ugrađeni sort (C++)

U praksi gotovo uvijek koristimo gotove implementacije — cilj je uštedjeti vrijeme za razmišljanje. std::sort je introsort (quick sort + heap sort + insertion sort), O(n log n) u najgorem slučaju.


vector<int> v = {4,2,5,3,8,5,8,3};
sort(v.begin(), v.end());

int n = 8;
int a[] = {4,2,5,3,8,5,8,3};
sort(a, a + n);

string s = "sladoled";
sort(s.begin(), s.end()); // addellos

reverse(first, last) okreće poredak elemenata na pozicijama [first, last⟩ u O(n): reverse(v.begin()+1, v.begin()+5) pretvara 1,2,3,4,5,6,7,8 u 1,5,4,3,2,6,7,8.

Komparator

Treći argument funkcije sort je operator usporedbe (komparator). C++ parove sortira prvo po prvom, pa po drugom elementu. Želimo li drugačiji kriterij, pišemo vanjski komparator: funkciju koja za a i b vraća true ako a mora doći prije b.

Primjer desno sortira parove po drugom elementu, a pri jednakosti po prvom.

Oprez Komparator mora biti strogi slabi poredak: comp(a, a) mora biti false. Pišite <, nikad <=.

#include <bits/stdc++.h>
#define pii pair<int,int>
using namespace std;

bool comp(pii a, pii b) {
    if (a.second == b.second)
        return a.first < b.first;
    return a.second < b.second;
}

int main() {
    vector<pii> v; // ... dodavanje parova
    sort(v.begin(), v.end(), comp);
    return 0;
}
Poglavlje 2

Binarno pretraživanje

Dana je sortirana lista od n brojeva. Nalazi li se u njoj broj x?

Igra pogađanja broja

Prva ideja: prođi kroz sve elemente i usporedi svaki s x — O(n). Pomaže li nam to što je niz sortiran?

Sigurno ste igrali igru u kojoj osoba zamisli broj od 1 do 100, a vi pogađate; nakon svakog pokušaja kaže je li njezin broj veći ili manji. Optimalno: prvo 50. Ako je veći — 75. Svakim pitanjem problem se prepolovi.

Ideja Ako se broj kandidata svakim korakom prepolovi, nakon k koraka ostaje ih n / 2k. Do jednog kandidata treba k = ⌈log₂ n⌉ koraka: za n = 100 to je 7, za n = 10⁶ samo 20, za n = 10⁹ tek 30.

Isto radimo pri traženju riječi u rječniku ili stranice u knjizi.

Binarno pretraživanje u sortiranom nizu

U svakom koraku usporedimo x s elementom na sredini intervala [l, r]. Ako je x manji, nastavljamo u lijevoj polovici; ako je veći, u desnoj. Isprobajte prisutan i odsutan broj.

Sivo = isključeno iz pretrage, plavo = još moguće, narančasto = sredina koju upravo uspoređujemo.

Implementacija

Klasična petlja: l i r su granice intervala koji još pretražujemo.


int l = 0, r = n - 1;

while (l <= r) {
    int mid = (l + r) / 2;
    if (array[mid] == x) {
        // pronašli smo x na poziciji mid
    }
    if (array[mid] > x) r = mid - 1;
    else l = mid + 1;
}

Varijanta s koracima: na početku radimo velike korake, a kako se približavamo odgovoru, koraci se prepolavljaju.


int k = 0; // trenutna pozicija u listi
for (int b = n / 2; b >= 1; b /= 2) {
    // ako korakom ne bismo preskočili x,
    // napravimo korak
    while (k + b < n && array[k + b] <= x) k += b;
}
if (array[k] == x) {
    // pronašli smo x na poziciji k
}

Obje varijante prepolove interval u svakom koraku: O(log₂ n). Varijantu s koracima zapamtite — u 3. poglavlju vidjet ćemo da ona čita binarni zapis tražene pozicije, bit po bit.

U varijanti s koracima za n koji je potencija broja 2, petlja while izvrši se najviše jednom po koraku; b = n/2, n/4, ..., 1 su upravo težine bitova pozicije.

C++ funkcije: lower_bound, upper_bound, equal_range

Standardna biblioteka ima gotove funkcije u logaritamskoj složenosti:

  • lower_bound — iterator na prvu vrijednost koja je barem x
  • upper_bound — iterator na prvu vrijednost koja je veća od x
  • equal_range — oba iteratora odjednom; ako x nema, oboje pokazuju na mjesto gdje bi bio

vector<int> v = {5,5,5,6,6,6,7,7};

auto lower = lower_bound(v.begin(), v.end(), 6);
auto upper = upper_bound(v.begin(), v.end(), 6);

cout << "lower_bound: " << (lower - v.begin()) << '\n'; // 3
cout << "upper_bound: " << (upper - v.begin()) << '\n'; // 6
// broj šestica = upper - lower = 3
Oprez Sve navedene funkcije podrazumijevaju da je niz sortiran. Ako nije, rezultat je besmislen (i nema greške!).

Primjena: pretraživanje rješenja

Tražimo najmanju veličinu kvadratnog kaveza d u kojoj su svi majmuni zadovoljni. Provjera za zadani d je laka, ali isprobavanje d = 1, 2, 3, … redom gotovo je uvijek presporo.

Ključno: sve veličine do neke granične uvjet ne ispunjavaju, a sve veće ga ispunjavaju — uvjet je monoton. Binarno pretražujemo tu granicu po d; u svakom koraku provjerimo uvjet umjesto da uspoređujemo brojeve.

Lijeva granica je 1, desna neki veliki broj koji sigurno zadovoljava. Zadovoljava li mid, pomičemo desnu granicu (želimo manje), inače lijevu.

Primjena: maksimum funkcije

Binarnu pretragu možemo koristiti i za traženje maksimuma funkcije koja prvo raste, a potom pada: vrijedi f(x) < f(x+1) za x < k i f(x) > f(x+1) za x ≥ k. Tražimo k.

Uvjet f(x) < f(x+1) („još rastemo”) je monoton: vrijedi, vrijedi, …, pa prestaje vrijediti. To je isti oblik kao kod kaveza — binarno tražimo granicu.

Primijetite Uzastopne vrijednosti funkcije ne smiju biti jednake; inače ne znamo na koju stranu nastaviti.

int x = -1;
for (int b = z; b >= 1; b /= 2) {
    while (f(x + b) < f(x + b + 1)) x += b;
}
int k = x + 1; // pozicija maksimuma

z je najveći korak, npr. najmanja potencija broja 2 koja je barem veličina domene.

Poglavlje 3

Pretraživanje kao postavljanje pitanja

Koliko je pitanje vrijedno? Zašto je binarno pretraživanje optimalno? Što je zapravo kod elementa?

Igra pitanja

Zamislimo skup S od n elemenata. Jedan je traženi, ali ne znamo koji. Smijemo postavljati samo pitanja oblika „Je li traženi element u podskupu A ⊆ S?” i dobivamo odgovor DA ili NE.

  • Linearno pretraživanje: A je jednočlan — „je li to element i?”
  • Binarno pretraživanje: A je polovica preostalih kandidata.
  • Sam biraj: možete li smisliti bolju strategiju od polovljenja?
Prvo linearno: pokazati da NE na 16 kandidata nosi samo 0,09 bita. Zatim polovljenje: svaki odgovor točno 1 bit, 4 pitanja. Na kraju dati studentima da probaju „sam biraj” i vide da nikakav podskup ne može isključiti više od pola kandidata u gorem ishodu.

Jedan odgovor = najviše jedan bit

  • Nakon k pitanja postoji najviše 2k različitih nizova odgovora.
  • Dva elementa s istim nizom odgovora ne možemo razlikovati — strategija bi za oba zaključila isto.
  • Da bismo razlikovali n elemenata treba 2k ≥ n, tj. k ≥ ⌈log₂ n⌉ pitanja u najgorem slučaju — za bilo koju strategiju.
  • Binarno pretraživanje troši točno ⌈log₂ n⌉ pitanja: optimalno je.

Zašto baš polovica? Ako pitanje dijeli m kandidata na |A| i m − |A|, u gorem ishodu ostaje ih max(|A|, m − |A|) ≥ m/2. Nijedno pitanje ne može u najgorem slučaju isključiti više od polovice.

Mjera informacije Ako je prije odgovora bilo m kandidata, a nakon njega m′, odgovor je donio log₂(m / m′) bita. Polovljenje: točno 1 bit. Odgovor NE na „je li to element 7?” pri m = 16: log₂(16/15) ≈ 0,09 bita.

Jedinica bit (binary digit) upravo je „jedan odgovor DA/NE”. Element među n kandidata nosi log₂ n bita informacije.

Zašto sortiranost pomaže?

Usporedba je pitanje. Ali koje pitanje jednom usporedbom možemo postaviti ovisi o tome što već znamo o podacima.

Sortiran niz Usporedba x < a[mid] odgovara na pitanje „je li pozicija traženog u {l, …, mid−1}?” — podskup od polovice kandidata, 1 bit. Ukupno ⌈log₂ n⌉ usporedbi.
Nesortiran niz Usporedba x == a[i] odgovara samo na „je li to a[i]?” — podskup od jednog elementa, gotovo 0 bita. Ako x nema u nizu, to ne možemo zaključiti dok ne provjerimo svih n.

Sortiranje nam unaprijed „kupuje” mogućnost postavljanja dobrih pitanja. Zato se isplati jednom sortirati (n log n) pa mnogo puta pretraživati (log n po upitu). Istu ideju koriste i binarna stabla pretraživanja, i lower_bound, i pretraživanje po rješenju: u svim slučajevima monotonost nam dopušta pitanje o polovici.

Binarno pretraživanje kao kodiranje

Svaka strategija pitanja je binarno stablo: unutarnji čvor = pitanje, djeca = odgovori, list = zaključak. Put od korijena do lista, zapisan bitovima, je kod elementa; pretraživanje = čitanje koda, bit po bit.

Binarna stabla i donja granica

  • Binarno stablo dubine d ima najviše 2d listova.
  • Trebamo barem n listova (svaki element svoj zaključak) ⇒ d ≥ ⌈log₂ n⌉.
  • Najgori slučaj = dubina stabla. Prosječni slučaj = prosječna duljina koda.
  • Uravnoteženo stablo (binarno pretraživanje) minimizira oboje; degenerirano stablo (linearno pretraživanje) ima dubinu n − 1.
  • Kodovi su prefiksni: nijedan kod nije početak drugoga, jer stajemo čim dođemo do lista.
Veza s kodom iz 2. poglavlja Varijanta s koracima b = n/2, n/4, …, 1 odlučuje u svakom koraku jedan bit tražene pozicije, od najznačajnijeg prema najmanje značajnom: k += b znači „taj bit je 1”. Binarno pretraživanje doslovno piše binarni zapis odgovora.
Dalje Ista slika objašnjava zašto su operacije nad uravnoteženim binarnim stablom pretraživanja O(log n), a nad degeneriranim O(n).

Nejednake vjerojatnosti: entropija

Što ako neke elemente tražimo češće? Neka element i tražimo s vjerojatnošću pi. Tada je očekivani broj pitanja bilo koje strategije barem H = ∑ pi · log₂(1 / pi) — Shannonova entropija (1948). Za jednake vjerojatnosti H = log₂ n.

Rijedak element smije imati dug kod, čest element kratak. Huffmanov algoritam gradi stablo s najmanjom očekivanom duljinom (uvijek < H + 1). Ako pitanja moraju biti oblika „x > a[m]?”, optimalno stablo je optimalno binarno stablo pretraživanja (dinamičko programiranje).

Što smo naučili

  • Usporedba je pitanje s odgovorom DA/NE; odgovor donosi najviše jedan bit.
  • Razlikovati n mogućnosti znači prikupiti log₂ n bita — zato je ⌈log₂ n⌉ donja granica, a binarno pretraživanje optimalno.
  • Strategija = binarno stablo = prefiksni kod. Dubina stabla = najgori slučaj.
  • Sortiranost (monotonost) je ono što nam omogućuje pitanja „o polovici”.
Najava Istu ideju primijenit ćemo na sortiranje: tamo je skup mogućih odgovora skup svih n! poredaka, a usporedba je pitanje o tom skupu. Zaključak: nužno je log₂ n! usporedbi.
Poglavlje 4

Ternarno pretraživanje

Što se dogodi ako niz dijelimo na tri dijela? I kada je to zaista korisno.

O algoritmu

Binarno pretraživanje dijeli niz na dva dijela. Ternarno ga dijeli na tri: umjesto jedne sredine biramo dvije,


mid1 = l + (r - l) / 3
mid2 = r - (r - l) / 3

Uspoređujemo x s a[mid1] i a[mid2]. Ako nismo pogodili, tri su slučaja:

  1. x < a[mid1]: nastavljamo u [l, mid1⟩
  2. x > a[mid2]: nastavljamo u ⟨mid2, r]
  3. inače: nastavljamo u ⟨mid1, mid2⟩

Problem se svodi na trećinu: log₃ n koraka.


int ternary_search(int l, int r, int x) {
    if (r >= l) {
        int mid1 = l + (r - l) / 3;
        int mid2 = r - (r - l) / 3;

        if (array[mid1] == x) return mid1;
        if (array[mid2] == x) return mid2;
        if (x < array[mid1])
            return ternary_search(l, mid1 - 1, x);
        else if (x > array[mid2])
            return ternary_search(mid2 + 1, r, x);
        else
            return ternary_search(mid1 + 1, mid2 - 1, x);
    }
    return -1; // nema ga
}

Je li ternarno brže od binarnog?

Manje koraka, da: log₃ n < log₂ n. Ali brojimo usporedbe, a svaki korak ternarnog pretraživanja treba dvije:

2 · log₃ n = (2 / log₂ 3) · log₂ n ≈ 1,26 · log₂ n

Razlog je informacijski: dva pitanja DA/NE mogu razlikovati četiri ishoda, a ternarni korak iskoristi samo tri. Dio informacije ostaje neiskorišten.

Općenito, dijeljenje na b dijelova traži (b − 1) usporedbi po koraku: (b−1) logb n usporedbi, što je najmanje upravo za b = 2.

n = 10³n = 10⁶
binarno, usporedbi1020
ternarno, koraka713
ternarno, usporedbi1426
Pouka Više dijelova ≠ brže. Broji se broj pitanja, a jedno pitanje donosi najviše jedan bit.

Implementacija na realnom intervalu

Na intervalu realnih brojeva ne možemo provjeravati jednakost — računala zaokružuju. Provjeravamo razlikuju li se brojevi do na neki mali ε, a petlju zaustavljamo kad interval postane kraći od ε.


double epsilon = 1e-7;

double ternary_search(double l, double r, double fx) {
    if (r - l > epsilon) {
        double mid1 = l + (r - l) / 3;
        double mid2 = r - (r - l) / 3;

        if (abs(f(mid1) - fx) < epsilon) return mid1;
        // ... analogno kao za cijele brojeve
    }
    // ...
}

Broj koraka je log3/2((r − l) / ε) ili log₃, ovisno o varijanti — u praksi fiksan broj iteracija (npr. 100 ili 200) umjesto usporedbe s ε.

Lokalni ekstremi: unimodalne funkcije

Za sortirane nizove binarno pretraživanje je dovoljno. Ternarno je našlo pravu primjenu u traženju ekstrema funkcija: funkcija koja prvo raste pa pada (unimodalna). Dijelimo interval s m₁, m₂ i usporedimo f(m₁) i f(m₂):

  1. f(m₁) < f(m₂): maksimum nije lijevo od m₁ (m₁ je u rastućem dijelu) → [m₁, r]
  2. f(m₁) > f(m₂): maksimum nije desno od m₂ → [l, m₂]
  3. f(m₁) = f(m₂): maksimum je između njih — bilo koji od prva dva odabira je ispravan

Svaki korak odbacuje trećinu intervala s jednom usporedbom.

Pokrenuti najprije asimetričnu, pa „dva vrha”: pokazati kako algoritam odbaci trećinu u kojoj je pravi maksimum i konvergira prema pogrešnom vrhu.

Što ako funkcija ima više ekstrema?

Algoritam radi samo za funkcije s jednim ekstremom (unimodalne). Ako ih ima više, rješenje zvuči naivno, ali radi: pogledajte graf, odaberite interval oko ekstrema koji vas zanima tako da ne obuhvaća nijedan drugi, i ternarno pretražite samo taj interval.

Primijetite Na cjelobrojnoj domeni umjesto ternarnog možemo binarno pretraživati granicu uvjeta f(x) < f(x+1) (2. poglavlje): jedna usporedba po koraku prepolovi interval, dok ga ternarno smanji samo na dvije trećine (log3/2 n ≈ 1,71 · log₂ n koraka).

Zlatni rez (golden-section search) je poboljšanje za realne funkcije: bira m₁, m₂ tako da se jedna od njih u sljedećem koraku ponovno iskoristi, pa treba samo jedno novo izračunavanje f po koraku uz smanjenje intervala na ≈ 0,618.

Poglavlje 5

Bitonično sortiranje

Sortiranje u kojem je unaprijed poznato koje ćemo parove usporediti — i zato se može izvoditi paralelno.

Mreže za sortiranje

Merge sort i quick sort su adaptivni: koju usporedbu radimo sljedeću ovisi o rezultatima prethodnih. To je dobro za broj usporedbi, ali loše za sklopovlje i paralelizam.

Mreža komparatora (sorting network) je niz unaprijed zadanih usporedbi: komparator uzme dvije vrijednosti i vrati manju na jednu, veću na drugu žicu. Isti slijed komparatora radi za svaki ulaz.

  • Komparatori na istoj razini ne dijele žice → mogu raditi istodobno.
  • Vrijeme izvođenja na n/2 procesora = broj razina (dubina).
  • Primjena: GPU, SIMD instrukcije, sklopovlje, kriptografija (vrijeme neovisno o podacima).
Pitanje Kako sortirati bez da ikad „pogledamo” podatke prije nego odlučimo što uspoređujemo?

Odgovor Kena Batchera (1968): bitonično sortiranje — mreža dubine O(log² n) s O(n log² n) komparatora. Temelji se na posebnoj vrsti nizova koje je lako spojiti.

Bitonični niz

Niz je bitoničan ako najprije (ne nužno strogo) raste, a zatim pada — pri čemu jedan od dva dijela može biti prazan — ili je ciklički pomak takvog niza.

  • 1, 3, 5, 8, 6, 4, 2 — raste pa pada
  • 6, 8, 7, 3, 1, 2, 4 — ciklički pomak prethodnog oblika (pada pa raste)
  • 1, 2, 3, 4 i 4, 3, 2, 1 — sortirani nizovi su bitonični
  • 1, 2, 3, 5, 4, 6 — nije bitoničan (dva uspona)
Ključno opažanje Rastući sortirani niz + padajući sortirani niz = bitonični niz. Ako znamo sortirati bitonični niz, znamo spojiti dva sortirana niza — a to je sve što merge sortu treba.

Polučistač (half-cleaner): ključna lema

Lema Neka je a[0..n−1] bitoničan, n paran. Za svaki i < n/2 usporedimo a[i] i a[i + n/2] i manji stavimo na mjesto i, veći na i + n/2. Tada:
  1. obje polovice su opet bitonične,
  2. svaki element prve polovice ≤ svakog elementa druge.

Ideja dokaza. Nacrtajmo prvu i drugu polovicu niza jednu preko druge. Budući da niz najprije raste pa pada, te se dvije krivulje sijeku najviše jednom. Lijevo od sjecišta minimume daje jedna krivulja, desno druga — niz minimuma je „zalijepljen” od dva komada bitoničnih krivulja i sam je bitoničan; isto za maksimume. A svaki minimum je, naravno, manji od svakog maksimuma iznad njega.

Bitonično spajanje: polučistač na n, pa rekurzivno na obje polovice. Nakon log₂ n razina niz je sortiran. Ukupno (n/2) · log₂ n komparatora, a sve usporedbe jedne razine su neovisne.

Bitonično spajanje — vizualizacija

Ulaz je bitoničan niz (raste pa pada). Razine su polučistači na udaljenosti j = n/2, n/4, …, 1. Nakon prve razine sve lijevo je manje od svega desno.

Cijela mreža: sortiraj polovice u suprotnim smjerovima, pa spoji

Rekurzija: sortiraj prvu polovicu rastuće, drugu padajuće (ista mreža sa zrcaljenim komparatorima) → dobiješ bitoničan niz → bitonično spoji. Iterativno: blokovi veličine k = 2, 4, …, n; unutar bloka parovi na udaljenosti j = k/2, …, 1; smjer bloka određuje bit k indeksa.


// n je potencija broja 2
for (int k = 2; k <= n; k *= 2)           // veličina blokova koje spajamo
    for (int j = k / 2; j >= 1; j /= 2)   // udaljenost uspoređivanih parova
        for (int i = 0; i < n; i++) {
            int l = i ^ j;                 // partner elementa i
            if (l > i) {
                bool rastuci = (i & k) == 0;
                if (rastuci ? a[i] > a[l] : a[i] < a[l])
                    swap(a[i], a[l]);
            }
        }

Brojanje. Dubina (broj razina): D(n) = D(n/2) + log₂ n = log₂ n · (log₂ n + 1) / 2 Komparatori: C(n) = 2·C(n/2) + (n/2)·log₂ n = (n/4) · log₂ n · (log₂ n + 1)

Za n = 8: 6 razina, 24 komparatora. Za n = 16: 10 razina, 80 komparatora.

Unutarnja petlja po i je ono što se izvodi paralelno — sve usporedbe iste razine su neovisne.

Cijela mreža — vizualizacija

Sive trake su faze k (veličina blokova koji se spajaju). Plavi blokovi se sortiraju rastuće, narančasti padajuće; dva susjedna bloka zajedno čine bitoničan niz za sljedeću fazu.

Poglavlje 6

Koje usporedbe određuju poredak?

Imamo rezultate nekih usporedbi. Kada iz njih slijedi jedan jedini poredak? Koliko ih je najmanje potrebno — i zašto ih ipak trebamo n log n?

Pokus: usporedi dok poredak ne bude jednoznačan

Vrijednosti elemenata su skrivene. Klikni dva elementa da ih usporediš: strelica pokazuje od manjeg prema većem. Rezultati usporedbi čine usmjereni graf, a tranzitivnost daje dodatne zaključke (ljubičasto). Desno: koliko je poredaka još u skladu sa svime što znamo.

Pustiti studente da predlažu usporedbe. Pokazati: (1) usporedba koja slijedi tranzitivno nosi 0 bita; (2) „Savjet” uvijek bira usporedbu koja dijeli poretke što ravnomjernije; (3) na kraju su tirkizne točno n−1 usporedbe susjeda. Za n = 5 donja granica je 7, i stvarno se može postići.

Teorem: nužne su točno usporedbe susjeda

Teorem Neka su x₁ < x₂ < … < xn elementi u (nama nepoznatom) pravom poretku. Skup rezultata usporedbi jednoznačno određuje poredak ako i samo ako su za svaki i elementi xi i xi+1 izravno uspoređeni.

(⇐) Iz x₁ < x₂, x₂ < x₃, …, xn−1 < xn tranzitivnošću slijedi odnos svakog para, dakle cijeli poredak. Nijedan drugi poredak nije u skladu s tim lancem.

(⇒) Pretpostavimo da xi i xi+1 nisu uspoređeni. Zamijenimo im mjesta. Svaka obavljena usporedba xi s nekim c ostaje točna: nema elementa između njih, pa je c ili manji od oba ili veći od oba. Postoje dakle dva poretka u skladu sa svim rezultatima — poredak nije određen.

Posljedica Najmanji skup usporedbi koji određuje poredak je jedinstven: n − 1 usporedbi susjeda — Hamiltonov put u grafu usporedbi. Svaka druga usporedba je suvišna: slijedi tranzitivno iz lanca.

U grafu: poredak je određen ⇔ tranzitivno zatvorenje je potpun poredak ⇔ graf ima jedinstveni topološki poredak ⇔ graf sadrži Hamiltonov put.

Kako konstruirati minimalni skup?

Konstrukcija: sortiraj, pa uzmi n − 1 susjednih parova. To je certifikat poretka: tko ga dobije, provjeri poredak s n − 1 usporedbi.

Kvaka: da bismo znali koji su parovi susjedni, moramo već znati poredak — a to je upravo ono što tražimo! Algoritam ne može unaprijed pogoditi susjede; usporedbe bira adaptivno, ovisno o prethodnim odgovorima.

Na kraju svakog sortiranja sve su usporedbe susjeda napravljene (teorem). Ostale usporedbe nisu „bačene”: one su bile potrebne da bismo otkrili tko je čiji susjed.

Provjera vs. pronalazak Provjeriti da je niz sortiran: n − 1 usporedbi.
Sortirati ga: barem ⌈log₂ n!⌉ ≈ n log₂ n − 1,44 n usporedbi.
Razlika između ta dva broja je cijena traženja certifikata.

Zašto baš log₂ n!? Odgovor daje poglavlje 3 — sljedeći slajd.

Donja granica za sortiranje: ⌈log₂ n!⌉

Prije prve usporedbe moguć je svaki od n! poredaka. Usporedba a < b? je pitanje DA/NE o skupu poredaka: poretke u kojima je a ispred b i one u kojima nije. U gorem ishodu ostaje barem polovica.

Poredak je određen tek kad ostane jedan kandidat. Dakle, po istom argumentu kao za pretraživanje:

broj usporedbi ≥ ⌈log₂ n!⌉ ≈ n log₂ n − 1,44 n

Stablo odluke algoritma za sortiranje ima n! listova, pa mu je dubina barem log₂ n!. Nijedan algoritam temeljen na usporedbama ne može bolje — ni std::sort, ni bilo koji budući.

merge sort: n⌈log₂ n⌉ − 2⌈log₂ n⌉ + 1; bubble sort: n(n−1)/2. Umetanje s binarnim pretraživanjem troši ∑⌈log₂ k⌉ ≈ log₂ n! usporedbi (ali O(n²) pomicanja). Ford–Johnson (1959) je još bliže granici.

Stablo odluke za n = 3

Svaki algoritam za sortiranje je binarno stablo: čvor = usporedba, list = poredak. Za tri elementa treba 3! = 6 listova, pa je dubina barem ⌈log₂ 6⌉ = 3. Stablo ispod to i postiže: 3 usporedbe u najgorem slučaju (a nekad samo 2).

Na svakom putu do lista prolazimo točno kroz usporedbe susjeda u tom poretku — plus eventualno jednu suvišnu. Npr. put do c < a < b: a < b (susjedi), b < c? ne — suvišna, a < c? ne — susjedi.

Što smo naučili

  • Rezultati usporedbi određuju poredak ⇔ svi susjedni parovi su uspoređeni izravno.
  • Minimalni takav skup je jedinstven i ima n − 1 usporedbi; sve ostale su tranzitivno suvišne.
  • Taj skup ne možemo unaprijed pogoditi: svaki algoritam ga mora pronaći, a to košta ⌈log₂ n!⌉ ≈ n log₂ n usporedbi u najgorem slučaju.
  • Isti informacijski argument kao kod binarnog pretraživanja: n! kandidata, jedan bit po pitanju.
Zatvoren krug Obećali smo u 1. poglavlju: „ne može brže od O(n log n)”. Sad znamo i zašto, i točno koliko.
Zaključak

Što ponijeti kući

  1. Sortiranje: O(n²) je lako, O(n log n) je standard, brže samo bez usporedbi.
  2. Binarno pretraživanje radi gdje god postoji monotonost: niz, uvjet, funkcija.
  3. Usporedba = pitanje = najviše 1 bit. Odatle log₂ n za pretraživanje i log₂ n! za sortiranje.
  4. Strategija pretraživanja = binarno stablo = kod; uravnoteženo je optimalno.
  5. Ternarno pretraživanje: za ekstreme unimodalnih funkcija, ne za sortirane nizove.
  6. Bitonične mreže: sve usporedbe unaprijed, O(log² n) paralelnih koraka.
  7. Poredak određuju usporedbe susjeda; teško ih je naći, lako provjeriti.

Zadaci za vježbu

Years (Codeforces 1424G)

  • Hint 1: ako imamo samo popis godina rođenja, koliko je ljudi rođeno prije neke godine? Da bismo efikasno odgovarali, prvo sortiramo i koristimo binarnu pretragu.
  • Hint 2: jedino godine kada se netko rodio ili umro mogu biti rješenje.
  • Hint 3: godine rođenja i smrti ne moramo vezati uz osobu — gledamo ih neovisno.
  • Rješenje: za svaku kandidatsku godinu g: (rođeni prije g) − (umrli prije g), oboje binarnom pretragom. O(n log n).

The Parade (Codeforces 1250J)

  • Hint 1: odaberimo veličinu reda r. Možemo li napraviti k redova veličine r? U kojoj složenosti to provjerimo?
  • Hint 2: provjera je linearna: pohlepno punimo redove, preostale vojnike prebacujemo u sljedeći red.
  • Rješenje: postoji granična veličina reda — binarno pretražimo r (pretraživanje rješenja!). Odgovor je r · k.

Još: Sorted Adjacent Differences, Worms.

Za razmišljanje: koliko najmanje usporedbi treba da bismo u najgorem slučaju sortirali 5 elemenata? (Odgovor: 7 — i to se postiže.)
