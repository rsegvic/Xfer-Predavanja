Poglavlje 1

Problem dinamičke povezanosti

„Jesu li a i b u istoj grupi?” i „spoji grupe od a i b” — mnogo puta, brzo.

Zadatak za zagrijavanje

U nekoj zemlji postoji n gradova i m cesta koje ih povezuju, a u svakom gradu na početku živi x ljudi. Tijekom vremena neke se ceste urušavaju. Dolaze dvije vrste upita:

  • D K — urušila se cesta K
  • P A x — populacija grada A postala je x

Nakon svakog upita treba reći koliko stanovnika ima trenutno najnaseljenija regija (skup gradova među kojima se može putovati cestama).

Razmislite Ceste samo nestaju, regije se samo dijele. Kako bismo to pratili? Puni tekst: CodeChef ABROADS. Rješenje dolazi na kraju 5. poglavlja — i bit će iznenađujuće jednostavno.

Dinamička povezanost

Imamo n elemenata raspoređenih u disjunktne skupove (nijedan element nije u dva skupa). Na početku je svaki element sam u svom skupu. Podržavamo dvije operacije:

  • same(a, b) — jesu li a i b u istom skupu?
  • unite(a, b) — spoji skup od a sa skupom od b

Skupovi se samo spajaju, nikad ne dijele. To ograničenje je ono što strukturu čini tako brzom.

Gdje se javlja:

  • komponente povezanosti grafa koji raste (dodaju se bridovi)
  • Kruskalov algoritam za minimalno razapinjuće stablo
  • otkrivanje ciklusa u neusmjerenom grafu
  • klase ekvivalencije: „a = b, b = c, je li a = c?”
  • segmentacija slike, perkolacija na mreži, unifikacija tipova u prevoditeljima

Pristup 1: polje oznaka

Svakom elementu zapišemo oznaku skupa. same je jedna usporedba. Ali unite mora prepisati oznaku svakog elementa jednog od skupova — prođe kroz cijelo polje.

Cijena same: O(1). unite: O(n). Niz od m unija: O(nm).
Prvo poboljšanje Pamtimo popis elemenata svakog skupa i uvijek prepisujemo manji skup. Svaki element promijeni oznaku najviše log₂ n puta → ukupno O(n log n). Zapamtite taj argument: vraća se u 6. poglavlju.

Pristup 2: šuma stabala

Svaki skup je stablo; element pamti samo roditelja (link[x]), a korijen je predstavnik. find se penje do korijena, unite spoji dva korijena. Nema prepisivanja — ali stabla mogu postati visoka: predložak „Lanac” (unije (1,0), (2,1), …) daje dubinu n − 1; isprobajte find(a) s a = 0.

Pustiti „Lanac” bez heuristika i find(0). Zatim uključiti uniju po veličini i opet „Lanac”: zvijezda. Zatim „Binomno”: dubina log n čak i s unijom po veličini — to je najgori slučaj za tu heuristiku.
Poglavlje 2

Struktura

Predstavnici, dvije operacije i prva heuristika: manji skup pod veći.

Union-find (disjoint set union)

Struktura raspodjeljuje elemente u skupove. Svaki skup ima predstavnika (representative), a elementi su lancem roditelja povezani s njim. Dva skupa spajamo tako da povežemo njihove predstavnike: jedan korijen postane dijete drugoga.

  • find(x) — vraća predstavnika skupa koji sadrži x
  • unite(a, b) — spaja skup od a i skup od b
  • same(a, b) — find(a) == find(b)
Ključna ideja Pamtimo samo roditelja. Spajanje je jedan zapis: link[b] = a. Sav posao seli se u find, koji se penje po stablu — pa je visina stabla sve što određuje cijenu.

Dvije heuristike drže stabla niskima: unija po veličini (ovo poglavlje) i kompresija puta (sljedeće). Zajedno daju gotovo konstantno vrijeme po operaciji.

Implementacija

Polje link: na i-tom mjestu roditelj elementa i (predstavnik pokazuje sam na sebe). Polje len: za predstavnike, veličina skupa. Na početku je svaki element sam svoj predstavnik, a sve veličine su 1.


for (int i = 0; i < n; i++) link[i] = i;
for (int i = 0; i < n; i++) len[i] = 1;

int find(int x) {
    while (x != link[x]) x = link[x];   // penji se do korijena
    return x;
}

bool same(int a, int b) {
    return find(a) == find(b);
}

unite nađe oba predstavnika i manji skup objesi pod veći:


void unite(int a, int b) {
    a = find(a);
    b = find(b);
    if (a == b) return;                 // već u istom skupu
    if (len[a] < len[b]) swap(a, b);    // a je veći
    len[a] += len[b];
    link[b] = a;                        // b-ov korijen pod a-ov
}

Memorija: dva polja cijelih brojeva. Bez rekurzije, bez pokazivača — zato je ovo jedna od najčešćih struktura na natjecanjima.

Unija po veličini: zašto log₂ n?

Lema Ako uvijek vješamo manji skup pod veći, svako stablo s k elemenata ima dubinu najviše log₂ k. Dakle find košta O(log n).

Dokaz. Pratimo jedan element x. Njegova dubina raste za 1 samo kad njegov korijen postane dijete drugog korijena. Tada se njegov skup spaja s barem jednako velikim, pa se veličina skupa barem udvostruči. Veličina ne može prijeći n, pa se to dogodi najviše log₂ n puta. ∎

Granica je dostižna: spajanjem jednako velikih skupova (parovi, pa četvorke, pa osmice…) nastaje binomno stablo dubine točno log₂ n. Predložak „Binomno” desno.

Unija po rangu: umjesto veličine pamtimo rang (gornju granicu visine), koji raste samo pri spajanju dvaju stabala istog ranga. Ista granica; koristi se u dokazu u 4. poglavlju.

Poglavlje 3

Kompresija puta

Kad se već penjemo do korijena, usput prevežimo sve što smo prošli izravno na njega.

Ideja: find koji popravlja stablo

find(x) prođe putem x → … → korijen. Sve čvorove na putu odmah prevežemo izravno na korijen: predstavnik ostaje isti, a sljedeći find bilo kojeg od njih košta jedan korak.


int find(int x) {
    if (link[x] == x) return x;
    return link[x] = find(link[x]);  // usput preveži x na korijen
}

Isto bez rekurzije (dva prolaza):


int find(int x) {
    int r = x;
    while (link[r] != r) r = link[r];           // 1. nađi korijen
    while (link[x] != r) {                      // 2. preveži put
        int nx = link[x]; link[x] = r; x = nx;
    }
    return r;
}

„Binomno”, pa u načinu klik: find kliknite 7: put se spljošti.

Varijante i što dobivamo

Prepolavljanje puta (path halving) — jedan prolaz, svaki čvor preskoči roditelja:


int find(int x) {
    while (link[x] != x) {
        link[x] = link[link[x]];   // preskoči jednu razinu
        x = link[x];
    }
    return x;
}

Razdvajanje puta (path splitting) je slično. Tarjan i van Leeuwen (1984) pokazali su da sve tri varijante imaju istu asimptotiku, a prepolavljanje je u praksi često najbrže.

heuristikejedan find, najgorepo operaciji, amortizirano
ništaO(n)O(n)
unija po veličiniO(log n)O(log n)
samo kompresijaO(n)O(log n)
obojeO(log n)O(α(n))

Samo kompresija: ukupno Θ(m · log1+m/n n) za m operacija. Oboje: O(m · α(n)), gdje je α inverzna Ackermannova funkcija — u praksi α(n) ≤ 4.

Što znači „amortizirano”? Sljedeće poglavlje.

Poglavlje 4

Koliko to zapravo košta?

Amortizirana analiza, mjerenje, skica dokaza i funkcija koja raste sporije od svega što ćete ikad sresti.

Amortizirana složenost

Pojedini find uz kompresiju može koštati O(log n) koraka. Ali taj isti posao popravi stablo, pa sljedeći pozivi budu jeftiniji. Pitamo zato:

Definicija Niz od m operacija ima amortiziranu cijenu T po operaciji ako ukupno košta najviše m · T — za svaki mogući niz. Pojedina operacija smije biti skuplja, dok je prosjek preko niza ograničen.

Poznati primjer: vector::push_back. Povremeno kopira cijelo polje (O(n)), ali udvostručavanje kapaciteta daje O(1) amortizirano.

Kako se to dokazuje? Metoda potencijala: skupa operacija smanjuje neku mjeru „nereda” u strukturi (ovdje: koliko su stabla visoka), a jeftine je operacije polako grade. Nered je ograničen, pa i ukupna cijena.

Za union-find Svaki niz od m operacija find/unite nad n elemenata, uz uniju po rangu i kompresiju puta, košta O(m · α(n)) (Tarjan, 1975). Nijedan pojedini find nije skuplji od O(log n).

Mjerenje u pregledniku

Koliko koraka (praćenja link[x]) troši prosječan find? Dva testa: slučajne unije i zlonamjerni „lanac”. Pokrenite i usporedite retke.

Primijetite: s obje heuristike prosječan find košta oko jedan korak, a najveća dubina nakon unija ostaje malena. Samo kompresija je u slučajnom testu gotovo jednako dobra — i zato ju mnogi natjecatelji koriste bez unije po veličini. Lanac pokazuje zašto je to ipak rizik bez druge heuristike… i zašto je kompresija sama ipak bitno bolja od ničega.

Bez heuristika: lanac dubine 9999, prosječan find ≈ 5000 koraka; u slučajnom testu dubina u tisućama. Unija po veličini: dubina ≤ 14. Samo kompresija na lancu: prvi find-ovi su skupi, kasnije jeftini — amortizacija na djelu.

Skica dokaza: O((m + n) · log* n)

Dokazujemo slabiju, ali i dalje nevjerojatnu granicu (Hopcroft i Ullman, 1973). Koristimo uniju po rangu: rang(x) je gornja granica visine podstabla kad je x bio korijen.

Svojstva rangova (sva se dokazuju u par redaka):

  1. Rang se mijenja samo dok je čvor korijen; kad postane dijete, zauvijek je fiksan.
  2. Na putu prema korijenu rangovi strogo rastu: rang(x) < rang(link[x]). Kompresija to čuva (novi roditelj je predak starog).
  3. Čvorova ranga r ima najviše n / 2r (podstablo ranga r ima bar 2r čvorova u trenutku nastanka, a ta su podstabla disjunktna).
  4. Najveći rang je ≤ log₂ n.

Grupiranje rangova u razrede. Rang r stavimo u razred prema log* r: razredi su {1}, {2}, {3, 4}, {5, …, 16}, {17, …, 65536}, … Svaki sljedeći razred seže do 2gornja granica prethodnog. Rangova ima ≤ log₂ n, pa razreda ima O(log* n).

log* log* n = koliko puta treba primijeniti log₂ da od n dođemo do ≤ 1. log* 65536 = 4, log* 265536 = 5. Za svaki n koji stane u računalo, log* n ≤ 5.

Skica dokaza: naplata koraka

Promotrimo find(x) i put x = v₀ → v₁ → … → korijen. Svaki korak vi → vi+1 naplaćujemo jednome od dvoje:

  • Operaciji, ako su rang(vi) i rang(vi+1) u različitim razredima (ili je vi+1 korijen ili njegovo dijete). Rangovi rastu duž puta, pa takvih koraka ima najviše O(log* n) po operaciji.
  • Čvoru vi, ako su u istom razredu. Nakon kompresije vi dobije novog roditelja s strogo većim rangom. Unutar razreda [r, 2r⟩ to se može dogoditi najviše 2r puta, a onda roditelj iskače iz razreda i čvor se više nikad ne naplaćuje.

Zbrajanje po razredima. U razredu koji počinje rangom r ima najviše n/2r + n/2r+1 + … ≤ 2n/2r čvorova, a svaki plaća najviše 2r puta: ukupno ≤ 2n po razredu. Razreda je O(log* n).

Rezultat Operacije plaćaju O(m · log* n), čvorovi O(n · log* n). Ukupno O((m + n) · log* n) Finija podjela rangova (Tarjan) daje O(m · α(n)). Ideja je ista: skupi koraci su rijetki jer svaki trajno popravi stablo.
Ključna rečenica: svaki korak naplaćujemo ili find-u (malo takvih po find-u) ili čvoru (malo takvih po čvoru ukupno). Nema trećeg. To je cijela amortizirana analiza.

Inverzna Ackermannova funkcija α(n)

Ackermannova funkcija raste brže od bilo koje eksponencijalne, dvostruko eksponencijalne, … funkcije. Njezin inverz α(n) raste sporije od bilo čega što ćete sresti:

n (do)α(n)log* n
312

204734
22047 (≈ 10616) i daleko više45 …

Za sve n do broja atoma u vidljivom svemiru (≈ 1080) vrijedi α(n) ≤ 4. U praksi je union-find konstantno vrijeme po operaciji.

Teorem (Tarjan, 1975) Uz uniju po rangu (ili veličini) i kompresiju puta, m operacija nad n elemenata košta O(m · α(n)).
A bolje? Ne. Fredman i Saks (1989): svaka struktura ove vrste treba Ω(α(n)) amortizirano po operaciji. Union-find je, dakle, optimalan — i jedna od rijetkih struktura čija je točna složenost poznata.

Seidel i Sharir (2005) daju moderni, kraći dokaz „odozgo prema dolje”.

Poglavlje 5

Primjene

Komponente i ciklusi, Kruskalov algoritam, brisanje unatrag — i rješenje zadatka s početka.

Komponente povezanosti i ciklusi

Neusmjereni graf dan je popisom bridova. Prolazimo bridove redom i spajamo krajeve. Brid čiji su krajevi već u istom skupu zatvara ciklus. Broj komponenti pada za 1 sa svakom uspješnom unijom.


int komponente = n;
for (auto [a, b] : bridovi) {
    if (same(a, b)) {
        // brid (a, b) zatvara ciklus
    } else {
        unite(a, b);
        komponente--;
    }
}
  • Graf je stablo ⇔ povezan i nijedan brid ne zatvara ciklus (ekvivalentno: m = n − 1 i povezan).
  • Radi i kad bridovi dolaze jedan po jedan (online) — za razliku od DFS-a, ne treba ponovno pretraživati.
  • Isto na mreži: polja su čvorovi, susjedna „kopnena” polja se spajaju → broj otoka, najveći otok, perkolacija.
Savjet Kad vidite „dodaj brid” i „jesu li povezani?” bez brisanja, union-find je gotovo uvijek pravi alat. S brisanjem — pogledajte slajd o brisanju unatrag.

Minimalno razapinjuće stablo i Kruskalov algoritam

Razapinjuće stablo grafa je podgraf sa svim vrhovima i nekim bridovima koji je stablo. Minimalno (MST) je ono s najmanjim zbrojem težina. Ne mora biti jedinstveno.

Kruskal: sortiraj bridove po težini i dodaj svaki koji ne zatvara ciklus. Provjera ciklusa je upravo same, dodavanje je unite.


vector<tuple<int,int,int>> edgeList;  // (w, a, b)
sort(edgeList.begin(), edgeList.end());
long long ukupno = 0;
for (auto [w, a, b] : edgeList) {
    if (same(a, b)) continue;          // ciklus
    unite(a, b);
    ukupno += w;
}

Složenost: O(m log m) za sortiranje; union-find dio je O(m · α(n)).

Zašto radi? Neka je e najlakši brid koji Kruskal dodaje između dva trenutno nespojena dijela. Svako razapinjuće stablo mora te dijelove spojiti nekim bridom f preko istog „reza”, a w(f) ≥ w(e). Zamjena f s e ne povećava težinu — pa postoji optimalno stablo koje sadrži e. Induktivno: Kruskalov izbor je uvijek dio nekog MST-a.

Primijetite Kruskalov algoritam je pohlepan: nikad ne odustaje od dodanog brida. Union-find mu daje provjeru ciklusa u gotovo konstantnom vremenu — bez njega bi svaka provjera bila obilazak grafa.

Kruskal — vizualizacija

Težina brida ≈ njegova duljina. Popis desno je sortiran; boja oboda vrha je njegov skup. Odbačeni bridovi (crveno) spajaju vrhove istog skupa.

Brisanje unatrag (offline trik)

Union-find ne zna brisati bridove. Ali ako su svi upiti poznati unaprijed (offline), brisanje čitano unatrag postaje dodavanje:

  1. Primijeni sva brisanja: izgradi strukturu od bridova koji prežive.
  2. Obrađuj upite od zadnjeg prema prvom. Odgovor na upit i je trenutno stanje; zatim „poništi” brisanje — dodaj brid natrag (unite).
  3. Ispiši odgovore u izvornom redoslijedu.

// upit i: obriši brid k_i; svi bridovi koji nisu
// ni u jednom upitu odmah su spojeni unite-om
for (int i = q - 1; i >= 0; i--) {
    odgovor[i] = komponente;        // stanje NAKON upita i
    if (!same(a[k_i], b[k_i])) komponente--;
    unite(a[k_i], b[k_i]);          // vrati brid
}

Rješenje zadatka s početka

Gradovi, ceste koje se urušavaju, promjene populacije, najnaseljenija regija nakon svakog upita.

  1. Pročitaj sve upite. Označi ceste koje se ikad uruše; preostale odmah spoji. Primijeni sve promjene populacije da dobiješ konačne populacije; za svaki upit P zapamti prethodnu vrijednost grada.
  2. Za svaki skup drži suma[predstavnik]; sve sume stavi u multiset.
  3. Upite obrađuj unatrag. Odgovor = najveći element multiseta.
    • D K unatrag = dodaj cestu: unite, izbriši dvije stare sume iz multiseta, ubaci zbroj.
    • P A x unatrag = vrati staru populaciju grada A: ažuriraj sumu njegovog skupa u multisetu.
Složenost Svaki upit: jedan find/unite (α(n)) i par operacija nad multisetom (log n). Ukupno O((n + m + q) log n).

Poanta nije u detaljima, nego u obratu: problem s brisanjem postao je problem s dodavanjem, a za dodavanje imamo gotovo besplatnu strukturu.

Isti trik rješava „broj parova nepovezanih gradova nakon svakog rušenja mosta”, „kad se dva vrha razdvoje” i slične zadatke — vidi popis na kraju.

Trik: „sljedeći slobodni”

Union-find nad indeksima: nxt[i] = najmanji još slobodan indeks ≥ i. Kad zauzmemo i, prevežemo ga na i + 1; kompresija puta onda preskače cijele blokove zauzetih polja.


// na početku nxt[i] = i za 0 ≤ i ≤ n (nxt[n] = n je "nema slobodnih")
int slobodan(int i) {
    return nxt[i] == i ? i : nxt[i] = slobodan(nxt[i]);
}
void zauzmi(int i) { nxt[i] = i + 1; }

// oboji sve još neobojene pozicije u [l, r]
for (int i = slobodan(l); i <= r; i = slobodan(i + 1)) {
    boja[i] = c;
    zauzmi(i);
}
  • Svaka pozicija se zauzme najviše jednom, pa je ukupno O((n + q) · α(n)) bez obzira na to koliko se intervali preklapaju.
  • Tipična primjena: bojanje intervala „zadnji sloj pobjeđuje” — obrađuj upite unatrag i boji samo još neobojeno.
  • Isti oblik: „k-ti slobodan stol”, „sljedeća neposjećena pozicija” u BFS-u po nizu, parkiranje.
Opća slika Union-find nije samo za grafove: svaki put kad se elementi trajno grupiraju ili kad pokazivač „sljedeći” samo napreduje, struktura daje gotovo konstantne operacije.
Poglavlje 6

Proširenja

Podaci po skupu, paritet i težine na putu, malo u veliko, vraćanje operacija.

Podaci po skupu

Sve što se može spojiti iz dva dijela možemo držati u predstavniku: veličinu, zbroj, najmanji element, broj bridova, bitmasku boja… Pri uniji spojimo vrijednosti u novom korijenu.


void unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) { bridova[a]++; return; }   // brid unutar skupa
    if (len[a] < len[b]) swap(a, b);
    link[b] = a;
    len[a]     += len[b];
    suma[a]    += suma[b];
    najmanji[a] = min(najmanji[a], najmanji[b]);
    bridova[a] += bridova[b] + 1;
}
  • Vrijednost je valjana samo u predstavniku; uvijek čitajte suma[find(x)].
  • Promjena vrijednosti jednog elementa: ažurirajte vrijednost njegova predstavnika.
  • „Broj bridova = broj vrhova” po komponenti (točno jedan ciklus), „je li komponenta stablo”, „zbroj populacije regije” iz zadatka s početka — sve isti obrazac.
Oprez Operacija mora biti asocijativna i računata samo iz dvaju dijelova. Medijan ili broj različitih vrijednosti to nisu — za njih treba trik „malo u veliko” (za dva slajda).

Union-find s paritetom: je li graf bipartitan?

Uz roditelja pamtimo i paritet puta do njega: par[x] ∈ {0, 1}. Paritet do korijena je zbroj (XOR) duž puta; kompresija ga usput zbraja. Brid (u, v) zahtijeva da u i v imaju različit paritet.

  • Različiti skupovi: spoji ih i postavi paritet korijena tako da uvjet vrijedi.
  • Isti skup, različit paritet: brid zatvara parni ciklus — u redu.
  • Isti skup, isti paritet: neparni ciklus → graf nije bipartitan.

Radi i online: bridovi dolaze jedan po jedan, a mi nakon svakog znamo je li graf još bipartitan. Isti mehanizam vodi „prijatelj/neprijatelj” relacije.

Implementacija s paritetom i općenito s težinama


int link[N], par[N];   // par[x] = paritet puta x → link[x]

pair<int,int> find(int x) {   // (predstavnik, paritet x → predstavnik)
    if (link[x] == x) return {x, 0};
    auto [r, p] = find(link[x]);
    link[x] = r; par[x] ^= p;    // kompresija: x sad pokazuje na r
    return {r, par[x]};
}

bool dodajBrid(int a, int b) {   // false = neparni ciklus
    auto [ra, pa] = find(a);
    auto [rb, pb] = find(b);
    if (ra == rb) return pa != pb;
    link[rb] = ra;
    par[rb] = pa ^ pb ^ 1;       // a i b dobiju različit paritet
    return true;
}

Težinski union-find. Umjesto parnosti pamtimo razliku: pot[x] = v(x) − v(link[x]). Uvjet „v(b) − v(a) = d” (npr. „b stoji d metara desno od a”) dodaje se isto kao brid, a nekonzistentan uvjet se otkrije usporedbom razlika.


// find vraća (r, v(x) − v(r)), uz pot[x] += d pri kompresiji
bool dodaj(int a, int b, long long d) {   // v(b) − v(a) = d
    auto [ra, da] = find(a);
    auto [rb, db] = find(b);
    if (ra == rb) return db - da == d;    // konzistentno?
    link[rb] = ra;
    pot[rb] = da + d - db;                // v(rb) − v(ra)
    return true;
}

Paritet je težinski union-find s vrijednostima modulo 2. Zadaci: People on a Line, Good Set Query.

Malo u veliko (small to large)

Treba li po skupu držati cijeli skup vrijednosti (npr. koliko različitih boja ima u komponenti), vrijednosti se ne mogu samo zbrojiti. Rješenje: svaki skup drži svoj set/map, a pri uniji manji prelijevamo u veći.


set<int> S[N];   // vrijednosti skupa, valjano samo u predstavniku

void unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) return;
    if (S[a].size() < S[b].size()) swap(a, b);
    for (int x : S[b]) S[a].insert(x);  // manji u veći
    S[b].clear();
    link[b] = a;
}
Lema Svaki element se preseli najviše log₂ n puta: pri svakom seljenju skup u kojem se nalazi barem se udvostruči. Ukupno O(n log n) umetanja, tj. O(n log² n) s set-om.

Isti argument kao za uniju po veličini u 2. poglavlju i za „prepiši manji skup” u 1. poglavlju — ovo je treći put da ga srećemo. Vrijedi ga zapamtiti kao obrazac: kad god spajate strukture, spajajte manju u veću.

Zadatak: Confluence (ABC 183 F) — po komponenti map razred → broj učenika.

Vraćanje operacija (rollback)

Ponekad treba poništiti zadnju uniju (pretraživanje s vraćanjem, podjela po vremenu). Kompresija puta mijenja mnogo pokazivača odjednom, pa je se odričemo; unija po veličini ostaje i daje O(log n) po operaciji — i dalje odlično.


vector<pair<int,int>> stog;   // (dijete, stara veličina roditelja)

void unite(int a, int b) {        // BEZ kompresije puta
    a = find(a); b = find(b);
    if (a == b) { stog.push_back({-1, 0}); return; }
    if (len[a] < len[b]) swap(a, b);
    stog.push_back({b, len[a]});
    link[b] = a; len[a] += len[b];
}
void undo() {
    auto [b, stara] = stog.back(); stog.pop_back();
    if (b < 0) return;
    len[link[b]] = stara; link[b] = b;
}
  • Svaka unija promijeni točno dvije vrijednosti, pa je poništavanje O(1).
  • Poništavati se može samo u obrnutom redoslijedu (stog), ne proizvoljnu uniju.
  • Uz „segmentno stablo nad vremenom” (svaki brid živi na intervalu vremena) to rješava offline dinamičku povezanost s dodavanjem i brisanjem u O(log² n) po bridu — tema za neko sljedeće predavanje.
Sažetak proširenja Podaci po skupu: spoji u korijenu. Relacije (paritet, razlika): pamti ih na bridu prema roditelju. Cijeli skupovi: malo u veliko. Brisanje: unatrag ili s vraćanjem.
Zaključak

Što ponijeti kući

  1. Skupovi koji se samo spajaju: šuma stabala s roditeljskim pokazivačima, dvije operacije.
  2. Unija po veličini: dubina ≤ log₂ n. Kompresija puta: svaki find popravlja stablo.
  3. Zajedno: O(α(n)) amortizirano — i to je dokazano optimalno.
  4. Amortizirana analiza: skupe operacije su rijetke jer svaka trajno smanji nered.
  5. Primjene: komponente, ciklusi, Kruskal, brisanje unatrag, „sljedeći slobodni”.
  6. Proširenja: podaci u korijenu, paritet/težine na putu, malo u veliko, vraćanje.
